# Lab 10 - Automation Playbooks, Incident Runbook, SOC Metrics, and Exam Readiness

## Objective

Design Sentinel automation rules, playbooks, an incident runbook, SOC metrics, and an SC-200 exam readiness tracker.

## Scenario

Contoso wants consistent incident response and measurable SOC improvement.

## Tasks

### Step 1 - Design automation rules

Create:

| Trigger | Condition | Action |
|---------|-----------|--------|

Include incident creation, severity-based assignment, tagging, and suppression.

### Step 2 - Design playbooks

Create playbooks for:

- Phishing triage
- Risky user response
- Endpoint isolation approval
- Malware remediation notification

### Step 3 - Build incident runbook

Include:

- Triage
- Scope
- Containment
- Eradication
- Recovery
- Communication
- Lessons learned

### Step 4 - Define SOC metrics

Create:

| Metric | Definition | Target |
|--------|------------|--------|

Include MTTD, MTTR, incident backlog, false positive rate, automation rate, and hunting findings.

### Step 5 - Build readiness tracker

Create:

| SC-200 area | Confidence 1-5 | Evidence from labs | Next study action |
|-------------|----------------|--------------------|-------------------|

Use:

- Manage a security operations environment
- Respond to security incidents
- Perform threat hunting

## Deliverable

Submit automation rule plan, playbook designs, incident runbook, SOC metrics table, and SC-200 readiness tracker.

## Checkpoint questions

1. Which automation action should require human approval?
2. Why are SOC metrics useful?
3. Which SC-200 domain needs your most review?
