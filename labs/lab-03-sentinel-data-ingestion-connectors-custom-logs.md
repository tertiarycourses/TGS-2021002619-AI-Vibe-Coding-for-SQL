# Lab 3 - Ingest Data into Sentinel with AMA, WEF, Syslog, CEF, Azure Diagnostics, Threat Indicators, and Custom Logs

## Objective

Select and design Sentinel data connectors and ingestion methods for Windows, Linux, Azure, threat intelligence, and custom logs.

## Scenario

Contoso needs to ingest endpoint, server, firewall, Azure, and threat intelligence signals into Sentinel.

## Tasks

### Step 1 - Create data source inventory

Create:

| Source | Connector or method | Log type | Priority |
|--------|---------------------|----------|----------|

### Step 2 - Plan Windows events with AMA

Document:

- Data collection rule
- Target machines
- Security event levels
- Workspace destination
- Validation query

### Step 3 - Plan WEF, Syslog, and CEF

Create:

| Source | Collection method | Collector requirement |
|--------|-------------------|-----------------------|

### Step 4 - Plan Azure diagnostics and threat indicators

Document:

- Azure Policy use
- Resource diagnostic settings
- Threat indicator source
- Validation method

### Step 5 - Design custom log table

Define:

- Custom table name
- Columns
- Sample record
- Parser need
- Retention

## Deliverable

Submit data source inventory, AMA plan, WEF/Syslog/CEF plan, Azure/threat indicator plan, and custom log design.

## Checkpoint questions

1. Why is connector selection based on data source requirements?
2. What does a data collection rule do?
3. When is a custom log table needed?
